# Устройство agentops

Подробности к [README](../README.md): как считается вердикт, откуда берутся разборы, что делает каждая команда.

## Как устроено

**Вердикт по тестам, а не по словам агента.** Тесты запускаются в свежей копии `testbed/`, куда переносятся только версии агента для исходных (не тестовых) `.go`-файлов проекта: добавленные агентом файлы, правки тестов, `go.mod`, `go.work` и `vendor/` не учитываются. Что проверяется: каждый исходный `Test…` должен дать событие `pass` в `go test -count=1 -json ./...`, и команда должна завершиться с кодом 0. Перед запуском версия агента отклоняется, если она не разбирается как Go-код, добавляет `init()` или добавляет импорт не из короткого списка чистых пакетов (`strings`, `strconv`, `sort`, `math`, `unicode/utf8` и подобные); так закрыты известные способы завершить тестовый процесс раньше времени или добраться до ОС. Что остаётся: код, подстроенный под входные данные тестов, пройдёт — это предел любого вердикта по тестам; список разрешённых импортов подходит этому проекту и слишком строг для произвольного, следующий шаг — судья в песочнице, до процесса которого код агента не дотянется. Агент и написанный им код работают без песочницы, от имени текущего пользователя, поэтому недоверенную задачу записывайте в контейнере или виртуальной машине.

**Трейсы, которые можно публиковать.** Трейс проходит через белый список: остаются только строки `init`, `assistant`, `user`, `result` и в них только перечисленные поля (модель, версия CLI, режим прав, текст и рассуждения, вызовы инструментов и их результаты, токены, цена, длительности и метки времени, отказы в правах). Отбрасываются данные аккаунта и лимитов, срок действия учётных данных, идентификаторы запросов и сессий, пути хоста, списки плагинов и инструментов, дублирующиеся данные инструментов; значение неожиданной формы отбрасывается целиком. Затем рабочий каталог заменяется на `/work`, системный временный каталог на `/tmp`, домашний на `~`, имя хоста на `host`, полное имя и логин на `user` (без учёта регистра, только целыми словами); то же в выводе тестов и в stderr агента. Claude работает с `TZ=UTC`, только с инструментами сценария (`--tools`) и с `--restricted`: файлы вне рабочего каталога ему недоступны ни через Read, ни через Bash, поэтому их содержимое не попадает в трейс. Текст любого файла навыка, который `agentops` дал агенту (всё под `plugin/skills/`), вырезается из выводов по содержимому, каким бы способом его ни прочитали: строки файла длиной от 24 символов заменяют весь вывод на `[текст навыка не сохраняется]`. `scripts/leakcheck.sh [каталог]` проверяет, что в прогонах не осталось ни имени, ни путей, ни служебных полей; свои имена (машины, работодателя) можно добавить в `AGENTOPS_LEAK_EXTRA` через `|`, без учёта регистра.

**Сначала правила, потом модель.** `analyze` сначала применяет правила: агент не начал работу, ему запрещена правка файлов, он упёрся в лимит ходов, не уложился во время. Модель (по умолчанию `haiku`, без инструментов, в пустом каталоге) вызывается только там, где правила не решают, с коротким промптом из шагов, вывода тестов и задания; её цена записывается в `postmortem.json`.

**Отказы и подсказка без модели.** `denials` берёт заблокированные шаги всех прогонов и относит каждый к одной причине по тексту его вывода, первое совпадение выигрывает: составная команда («contains multiple operations»; части после «require approval» сводятся к имени команды; здесь и в остальных причинах не считаются командами, заведомо разрешёнными в этих прогонах: `go test`, `cat`, `ls`, `pwd`, `echo`, `printf`, `head`, `tail`, `grep`, `rg`, `wc`, `cd`, `true` и `sed` без `-i`, а если в шаге остались только они, берётся последняя; тела here-документов пропускаются), переменная или цикл («can't be checked before it runs»), отключённый инструмент («No such tool available»), команда не разрешена («requires approval»), песочница («operation not permitted», «read-only file system» или любой заблокированный шаг Codex), иначе «другое». Подсказка для каждой причины — готовая английская фраза из шаблона с подставленными именами команд или инструментов; правила детерминированы, модель не вызывается.

**`check` как гейт CI.** Печатает долю успешных прогонов и возвращает код 1, если она ниже порога (`--min`, по умолчанию 80%).

Прогоны — обычные файлы: `runs/<id>/meta.json` (сценарий, модель, задание, вердикт), `trace.jsonl` (очищенный трейс), `postmortem.json` (разбор). `scripts/record.sh` записывает набор из 17 прогонов (оба агента, в том числе сценарий `skill`), разбирает упавшие и запускает проверку утечек.

## Команды

Все команды, кроме интерактивного `tui`, принимают `--json`; выход машиночитаемый, точная схема — в `agentops schema`. Все, кроме `schema`, принимают `--runs <каталог>` (по умолчанию `$AGENTOPS_RUNS`, иначе `runs`). Флаги можно писать и после id. Без аргументов запускается `tui`. Таблица собрана по `agentops <команда> -h`.

| Команда | Что делает | Флаги |
|---------|------------|-------|
| `ls` | список прогонов и сводка | `--failed` только упавшие прогоны |
| `show <id>` | детали прогона и его шаги | `--step N` показать один шаг целиком; `--max-bytes K` предел размера входа и выхода шага в байтах (по умолчанию 4000, `0` — без предела) |
| `why <id>` | почему прогон упал | |
| `check` | проверить долю успешных прогонов (код выхода 1 ниже порога) | `--min` порог успешных прогонов, % (по умолчанию 80) |
| `denials` | отказы в правах по всем прогонам и подсказка агенту | `--agent` только прогоны этого агента; `--scenario` только прогоны этого сценария; `--hints` только подсказки агенту, по одной в строке |
| `schema` | схема JSON-вывода команд (JSON Schema, 2020-12) | |
| `run` | записать прогон агента на тестовом проекте | `--agent` (`claude` или `codex`), `--scenario` (по умолчанию `baseline`), `--plugin` (`plugin`, нужен сценарию `skill`), `--model` (у claude `haiku`, у codex свой по умолчанию), `--n` (1), `--testbed` (`testbed`) |
| `analyze [id…]` | автоматический разбор упавших прогонов | `--model` (`haiku`), `--force` разобрать заново |
| `tui` | интерактивный просмотр прогонов | |

Сценарии `run`: `baseline`; `no-edit` (правка файлов запрещена); `few-turns` (3 хода); `one-turn` (1 ход); `bad-task` (задание с неверной подсказкой); `skill` (как `baseline`, но агенту доступен навык `go-test-fixer` из `plugin/`: у Claude без `--safe-mode` и с `--plugin-dir`, у Codex навык кладётся в `.agents/skills/` рабочей копии, плагины профиля остаются выключенными, а `skill_search` и `skill_mcp_dependency_install` включены). `--plugin` нужен сценарию `skill` у обоих агентов.

**Два агента и что они использовали.** `run --agent codex` пишет прогон Codex CLI (`codex exec --json`, путь к бинарю можно задать через `AGENTOPS_CODEX_BIN`). Его события идут в трейс через такой же белый список с теми же заменами; метки времени `ts` добавляет сам `agentops`, потому что Codex их не пишет. Оба агента получают только переменные окружения из белого списка (`PATH`, `HOME`, `USER`, `LANG`, `TMPDIR`, прокси и `SSL_CERT_FILE`) и ключ своего провайдера (`ANTHROPIC_API_KEY` у Claude; `OPENAI_API_KEY` и `CODEX_HOME` у Codex), остальное от родительской оболочки не наследуется. Codex работает в песочнице (`workspace-write`, а в `no-edit` — `read-only`), с отключёнными плагинами, хуками, памятью и коннекторами профиля (в сценарии `skill` плагины остаются выключенными, а демонстрационный навык копируется из `plugin/skills/` в `.agents/skills/` рабочей копии), и со своим кэшем сборки Go в `<кэш пользователя>/agentops/gocache`: в песочнице обычный кэш недоступен. Оба агента разбираются в одну модель: у каждого шага есть `kind` (`shell`, `read`, `edit`, `search`, `skill`, `mcp`, `subagent`, `web`, `other`) и, для навыка, MCP-инструмента и подагента, `name`; у прогона — `tokens_in`, `tokens_out`, `skills`, а в `show` ещё `mcp`, `subagents`, `web_calls`. Навык Codex определяется по чтению файла `…/skills/<имя>/SKILL.md`, а вывод команды, которая может напечатать такой файл, заменяется строкой `[текст навыка не сохраняется]`. У Claude навык виден как вызов инструмента Skill, а текст файла навыка, который Claude получает сообщением пользователя, заменяется тем же маркером.

У Codex нет аналога режима `--restricted` у Claude: песочница ограничивает запись, а не чтение, поэтому агент может прочитать файлы вне рабочего каталога. Прогоны Codex читайте глазами и проверяйте `scripts/leakcheck.sh` до публикации.

Что сравнимо между агентами: вердикт, число шагов, время, токены. Цена только у Claude (у Codex в `cost_usd` и в таблице `—`: он сообщает токены, а не деньги). Токены Codex берутся из последнего `turn.completed`, у Claude из `result.usage` с кэшем. У Codex нет лимита ходов, поэтому `few-turns` и `one-turn` для него не запускаются. `no-edit` у Codex — песочница только для чтения, в которой не работают и тесты, так что прогон падает иначе, чем у Claude.

`show <id> --step N` режет вход и выход шага отдельно: текст длиннее `--max-bytes` заменяется началом и концом (по половине предела), между ними строка `… [обрезано N байт] …`. В JSON размеры без обрезки лежат в `input_bytes` и `output_bytes`, а `truncated` говорит, что что-то обрезано. В TUI шаг открывается целиком.

`schema.json` не правится вручную: его генерирует `go test ./cmd/agentops -run TestSchemaIsCurrent -update` из типов в `cmd/agentops/output.go` и тегов `doc`/`enum` на их полях; тест падает, если файл расходится с кодом.
